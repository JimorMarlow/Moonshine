# Known problems

## Проверка на железе (после сборки макета и перепайки датчиков)

Ничего из этого пока не проверено: сначала нужно собрать тестовый макет и перепаять датчики потока на финальные разъёмы. Прошивка: `pio run -e esp32-wroom-38u -t upload`, лог: `pio device monitor -b 115200`.

### 1. Поток воды (v1.7.0)

- [ ] Открыть кран: `DF.Flow` / `Cool.Flow` в карточках и на схеме показывают расход в мл/мин, не ноль.
- [ ] Сверить с мерной ёмкостью: N мл за T секунд → `N*60/T` мл/мин; расхождение — повод откалибровать датчик кнопкой.
- [ ] Колёса на схеме меняют скорость по порогам: <150 мл/мин медленно, 150–250 средне, >250 быстро; анимация труб идёт по направлению потока.
- [ ] Закрыть игольчатый кран: расход уходит в 0 примерно за 10 с (окно измерения), колёса исчезают, появляется ⚠.
- [ ] Показания не «залипают» после остановки воды и восстанавливаются при повторной подаче.

### 2. Порог «нет воды» 5 мл/мин

- [ ] При закрытом кране — ровно 0 и ⚠ на обоих контурах.
- [ ] При нормальной подаче ложных «Нет воды в охладителе/дефлегматоре!» нет, в том числе когда расход дрожит у порога.
- [ ] Правила по температуре: `CoolT` > 30 °C при потоке 0 → красная ошибка, при потоке > 5 → жёлтое «Добавьте воды…»; `Heater` > 55 °C при потоке 0 → «Включите подачу воды».

### 3. Страница и chunked-ответ (v1.7.1)

- [ ] `GET /` в браузере: страница целиком, в заголовке версия 1.7.1.

### 4. Температуры (v1.7.0, этап 3)

# На будущее: serial-лог для DSH (Вариант B)

Заметка писалась под Windows (COM-порты, пути `C:\Users\jimor\...`), в проекте пока нет ни `tools/`, ни `logs/` — задача не начата.

**Задача:** дать агенту (DSH) читать вывод с платы, не мешая человеку и не конфликтуя за COM-порт.

**Почему не `monitor_filters = log2file`:**
`pio device monitor` не работает без интерактивного stdin — `platformio\device\monitor\terminal.py:102-109` бросает исключение и прямо советует читать порт через pyserial. В фоновой задаче DSH терминала нет, монитор падает на старте, `logs/` не появляется. Вариант A (`log2file`) годится только когда монитор держит открытым сам пользователь.

**Что сделать:**
- `tools/serial_log.py` — dumper на pyserial, пишет непрерывно в `logs/serial.log`.
- Python и библиотека уже есть, ставить ничего не надо:
  `C:\Users\jimor\.platformio\penv\Scripts\python.exe` (Python 3.11.7, pyserial 3.5).

**Требования к скрипту:**
- аргументы: `--port COM5` (или автоопределение единственного USB-порта), `--baud 115200`, `--out logs/serial.log`;
- флаг `--echo` — дублировать поток в stdout (tee), чтобы пользователь видел вывод прямо в своём терминале, как в мониторе, а DSH параллельно читал файл;
- открытие порта с `timeout=0.2`, чтение в цикле, `flush()` после каждой порции — чтобы DSH видел свежие строки;
- переоткрытие порта при обрыве/переподключении платы (не падать, писать в лог отметку о переподключении);
- ротация по размеру (например, 5 МБ → `serial.log.1`), чтобы не рос бесконечно;
- декодирование `errors="replace"`, чтобы нехорошие байты не валили цикл;
- при старте писать в лог строку вида `--- open COM5 115200 <время>`.

**Кто что видит (важно):**
- Порт эксклюзивен: либо `pio device monitor`, либо скрипт-дампер — одновременно нельзя.
- Смотреть «как монитор» можно только через запущенный скрипт: с `--echo` поток идёт в терминал пользователя, файл при этом пишется для DSH.
- Если скрипт запускает DSH в фоне (без пользователя), терминал у него свой — пользователь смотрит лог файлом: `Get-Content logs\serial.log -Tail 30 -Wait` или открыв файл в VS Code.
- Цветов/меню/меток времени монитора у дампера нет — это сырой поток; при желании `--echo` может добавлять префикс времени.
- Ввод с клавиатуры в порт не нужен: прошивка не читает Serial (`Serial.read`/`available`/`parseInt`/`write` в `src/` не встречаются), поэтому TX-канал дамперу не требуется.

**Запуск (пример):**
```powershell
# пользователь смотрит в терминале + файл пишется для DSH
& "C:\Users\jimor\.platformio\penv\Scripts\python.exe" tools\serial_log.py --port COM5 --baud 115200 --out logs\serial.log --echo

# только файл, без вывода в терминал (когда дампер поднимает DSH в фоне)
& "C:\Users\jimor\.platformio\penv\Scripts\python.exe" tools\serial_log.py --port COM5 --baud 115200 --out logs\serial.log
```
DSH читает `logs\serial.log` в обоих случаях (например, `Get-Content logs\serial.log -Tail 50 -Wait`).

**Проверка:**
- после подключения платы в `logs\serial.log` появляется `Moonshine v1.3.4 started...` и строки температур;
- с `--echo` те же строки идут в терминал пользователя;
- отключить/подключить плату — лог продолжается, есть отметка о переоткрытии;
- одновременно `pio device monitor` уже не запустить (порт эксклюзивен) — это ожидаемо.

**Мелочи:**
- добавить `logs/` в `.gitignore`, иначе логи попадут в коммит;
- в системе сейчас виден только COM1 (материнский порт), USB-переходник не подключён — проверять после подключения платы;
- для ESP8266 boot-сообщения идут на 74880 бод: при 115200 их не видно, при необходимости — отдельный короткий проход на этой скорости.
