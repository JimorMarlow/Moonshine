# Moonshine — инструкции для агентов

Контроллер ректификационной колонны на ESP8266 (NodeMCU v3): температура DS18B20,
датчики потока Холла, веб-интерфейс в LittleFS. Прошивка на PlatformIO + Arduino framework.

## Сборка и проверка

`pio` не в PATH — вызывай полный путь:

```powershell
& "$env:USERPROFILE\.platformio\penv\Scripts\pio.exe" run -e nodemcuv3
```

- Перед тем как сказать «готово», собери проект этой командой и покажи итог (RAM/Flash, ошибки).
- Ошибки компиляции читай из вывода целиком: сначала первая ошибка, остальные часто её следствие.
- Прошивка и монитор требуют подключённой платы — **спроси пользователя**, прежде чем заливать:

```powershell
& "$env:USERPROFILE\.platformio\penv\Scripts\pio.exe" run -e nodemcuv3 -t upload
& "$env:USERPROFILE\.platformio\penv\Scripts\pio.exe" device monitor -b 115200
```

- Полная очистка: `... pio run -t clean`. Не чисти `.pio` без причины — сборка станет дольше.
- Юнит-тестов в проекте нет; критерий корректности — успешная сборка плюс проверка логики чтением кода.

## Что важно не сломать

- `src/pinout.h` — фактические назначения пинов. Не меняй их без явного подтверждения пользователя.
- `platformio.ini` — зависимости зафиксированы (ETL, Gyver-библиотеки, LiquidCrystal_I2C).
  Новую библиотеку добавляй только по просьбе; версии не поднимай «заодно».
- `src/version.h` — версия прошивки; `sync_version.py` при сборке подставляет её в `package.json`.
  Поднимай PATCH при обычных правках, MINOR — при новых возможностях.
- Веб-интерфейс (`src/web-ui.cpp`) отдаётся из LittleFS; большие строки держи в PROGMEM,
  следи за свободной RAM (сборка печатает её в конце).
- Строки интерфейса и сообщения — на русском, как в существующем коде.
- Ничего не выкладывай в git самостоятельно, после завершения этапа разработки, если я попросил
  увеличить версию, подготовь текст с описанием коммита, покажи мне, я сам выложу после коррекции.

## Стиль

- Не переформатируй чужие файлы целиком: минимальный diff, тот же стиль, те же имена.
- Комментарии — по делу и на русском; не комментируй очевидное.
- Не трогай `.pio/`, `docs/`, `README.md` без необходимости.
- Коммиты короткие, на русском, в стиле истории (`v1.2.13 исправлен опрос DS18B20`).

## Порядок работы

1. Сначала прочитай затронутые файлы (и `README.md`), потом правь.
2. Меняй по одной логической вещи за раз, после каждой — сборка.
3. Для поиска по коду и проверки чужих правок используй сабагентов, но правки делай сам.
4. Если сборка падает по причине окружения (нет тулчейна, нет платы) — скажи об этом прямо,
   не выдавай это за ошибку кода.
