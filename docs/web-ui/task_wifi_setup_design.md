# WiFi Setup Page — Техническое задание

**Версия:** ESP Device v1.0.0

## Описание задачи

Разработать веб-интерфейс для первичной настройки WiFi подключения устройства на базе ESP8266/ESP32.

## Контекст

Устройство имеет два режима работы:
1. **Режим настройки (Setup Mode)** — точка доступа с именем `ESP_Device_AP` для первичной конфигурации
2. **Рабочий режим (Station Mode)** — подключение к домашней WiFi сети с доступом по mDNS `espdevice.local`

## Функциональные требования

### 1. Режимы работы

#### 1.1 Режим по умолчанию (AP Mode)
- При первом запуске или после сброса настроек устройство создаёт точку доступа
- **SSID:** `ESP_Device_AP`
- **Пароль:** `password123`
- **IP адрес:** `192.168.4.1`
- Веб-сервер доступен по адресу `http://192.168.4.1`
- **Редактирование:** пользователь может изменить SSID и пароль точки доступа до сохранения настроек

#### 1.2 Сброс к заводским настройкам
- Специальная кнопка (GPIO) удерживается при загрузке устройства (3-5 секунд)
- После сброса:
  - WiFi настройки очищаются
  - Устройство запускается в режиме точки доступа (п. 1.1)
  - Страница настройки WiFi доступна сразу после загрузки

#### 1.3 Рабочий режим (STA Mode)
- После успешной настройки устройство подключается к выбранной пользователем WiFi сети
- Веб-сервер доступен по:
  - mDNS: `http://espdevice.local`
  - IP адресу, выданному роутером

### 2. Страница настройки WiFi

#### 2.1 Основной функционал

1. **Сканирование доступных сетей**
   - Отображение списка обнаруженных WiFi сетей
   - Показывать: SSID, уровень сигнала (RSSI), тип защиты (WPA/WPA2/Open)
   - Сортировка по уровню сигнала (убывание)

2. **Выбор сети**
   - Клик по SSID для выбора
   - Автоматическое заполнение поля SSID
   - Индикация выбранной сети

3. **Ввод пароля**
   - Поле ввода пароля с возможностью показать/скрыть
   - Валидация: минимальная длина 8 символов
   - Для открытых сетей поле пароля скрыто

4. **Подключение**
   - Кнопка "Connect" / "Подключиться"
   - Индикация процесса подключения (анимация/прогресс)
   - Проверка успешности подключения
   - При ошибке — возврат к выбору сети

5. **Настройка точки доступа (AP Mode)**
   - Поля для редактирования SSID и пароля точки доступа
   - Валидация: SSID мин. 1 символ, пароль мин. 8 символов
   - Кнопка "Apply AP Settings" / "Применить настройки AP"

6. **Сохранение и перезагрузка**
   - Кнопка "Save & Reboot" / "Запомнить и перезапустить" (внизу страницы)
   - Сохранение настроек в энергонезависимой памяти (SPIFFS/LittleFS/EEPROM)
   - Перезагрузка устройства после сохранения
   - Редирект на страницу статуса через 10 секунд

#### 2.2 Сброс настроек

- Кнопка "Factory Reset" / "Сброс настроек" в нижней части страницы
- Подтверждение сброса (modal dialog)
- После сброса:
  - Очистка сохранённых WiFi настроек
  - Перезагрузка в режиме точки доступа
  - Возврат на эту же страницу настройки

#### 2.3 Статус подключения

- Индикация текущего статуса:
  - 🔴 Disconnected — не подключено
  - 🟡 Connecting... — подключение
  - 🟢 Connected — подключено, показывать SSID и IP
- Кнопка "Refresh" / "Обновить" для повторного сканирования

### 5. Технические требования

#### 5.1 Фронтенд

- **HTML5** с семантической разметкой
- **CSS3** с Flexbox/Grid для макета
- **Vanilla JavaScript** (без фреймворков для минимизации размера)
- **Fetch API** для AJAX запросов
- **localStorage** для сохранения выбора языка
- **Single Page Application** подход (без перезагрузки страниц)

#### 5.2 Бэкенд (ESP8266/ESP32)

- **HTTP сервер:** ESP8266WebServer / WebServer
- **API endpoints:**
  - `GET /` — страница настройки
  - `GET /api/scan` — сканирование сетей (JSON)
  - `POST /api/connect` — подключение к сети (JSON)
  - `GET /api/status` — статус подключения (JSON)
  - `POST /api/save` — сохранение настроек (JSON)
  - `POST /api/reset` — сброс настроек (JSON)
  - `POST /api/ap_settings` — настройка точки доступа (JSON)
- **Хранение данных:**
  - SPIFFS/LittleFS для HTML/CSS/JS файлов
  - EEPROM или Preferences для WiFi настроек
- **mDNS:** для доступа по имени в рабочем режиме

#### 5.2.1 Структура конфигурации (для библиотеки ETL)

```cpp
namespace etl::wifi {
    struct server_config_t {
        const char* hostname = "espdevice";           // Имя хоста для mDNS
        const char* ap_ssid = "ESP_Device_AP";        // SSID точки доступа по умолчанию
        const char* ap_password = "password123";      // Пароль точки доступа по умолчанию
        const char* sta_ssid = "";                    // SSID внешней сети (пусто = не подключено)
        const char* sta_password = "";                // Пароль внешней сети
        uint16_t port = 80;                           // Порт веб-сервера
    };
}
```

**Примечание для проекта Moonshine:**
- В проекте `Moonshine` структура конфигурации будет переопределена через `settings.h`
- Имя хоста: `"moonshine"`
- AP SSID: `"Moonshine_AP"`
- AP Password: `"moonshine123"`
- Версия в заголовке: `"Moonshine vX.X.X"` (из `version.h`)

#### 5.2.3 Стиль кодированя

для имен классов, структур и методов использовать snake_style - все буквы строчные с разделителм "_"

### 6. Сценарии использования

#### 6.1 Первичная настройка

1. Пользователь включает устройство
2. Устройство создаёт точку доступа `ESP_Device_AP`
3. Пользователь подключается к `ESP_Device_AP` с паролем `password123`
4. Открывает `http://192.168.4.1`
5. Видит список доступных сетей
6. Выбирает свою сеть, вводит пароль
7. Нажимает "Connect"
8. При успехе — "Save & Reboot"
9. Устройство перезагружается, подключается к домашней сети
10. Пользователь подключается к `http://espdevice.local`

#### 6.2 Сброс настроек

1. Пользователь зажимает кнопку при загрузке (3-5 сек)
2. Устройство загружается в режиме настройки
3. Все WiFi настройки сброшены
4. Пользователь настраивает заново (см. п. 6.1)

#### 6.3 Настройка точки доступа (AP Mode)

1. Пользователь открывает страницу настройки в режиме AP
2. Изменяет SSID точки доступа (например, на "MyDevice_AP")
3. Изменяет пароль (мин. 8 символов)
4. Нажимает "Apply AP Settings"
5. Точка доступа перезапускается с новыми настройками
6. Пользователь переподключается к новой сети

#### 6.4 Ошибка подключения

1. Пользователь вводит неверный пароль
2. Нажимает "Connect"
3. Получает ошибку "Connection failed"
4. Исправляет пароль
5. Повторяет попытку
